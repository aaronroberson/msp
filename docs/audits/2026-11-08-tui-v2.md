## Status 2026-11-08 — Runner Chat / Ask and Execution Logs tabs

Split the persistent runner panel into `Chat / Ask` and `Execution Logs` tabs. The logs tab contains the executed-command header, subprocess output, command input, Run, and Stop controls. Commands triggered by screen navigation, refresh, presets, and direct runner submission select the logs tab; subprocess output is always written there.

The Chat / Ask tab has its own question input and transcript. Submitting a question invokes the existing `msp ask <question> --json` command. The transcript displays only the user's prompt and the AI response (or a concise failure status); UI navigation/control messages and the command header stay in Execution Logs. AI command output is still recorded in Execution Logs for transparency.

## Status 2026-11-09 — Ask response parsing

Fixed the TUI Ask response parser. `msp ask --json` emits indented multi-line JSON, so parsing each streamed line separately discarded valid responses. Ask completion now parses the accumulated output using the same JSON extractor as the data views; an empty response reports the actual exit code or a no-response status. Verification: project-venv `py_compile`, multiline JSON parsing against the real output shape, and `git diff --check` passed.

## Status 2026-11-09 — Ask failure status and diagnostics

Follow-up from the user-reported `Ask Failed (0)`: the `msp ask` route called `AIAnalyzer.ask()` but ignored its `None` return when provider/API errors were caught. As a result, the subprocess exited 0 despite returning no answer. The CLI now exits 1 when the analyzer returns no response. The Chat tab also surfaces captured provider/API error lines (for example, missing-key or request errors) instead of only directing the user to logs. This makes the actual local provider configuration failure visible without sending a diagnostic query. Verification: `.venv/bin/python -m py_compile src/tui_v2.py src/main.py`, direct TUI import, and `git diff --check` passed.

## Status 2026-11-09 — Contextual process, firewall, and startup controls

Implemented the approved interaction extension in `src/tui_v2.py`, `src/network.py`, `src/startup.py`, and new `src/firewall.py`.

- Network rows now have a selected-item inspector with live process details and a graceful stop action. Stop sends SIGTERM, waits up to five seconds, and asks before SIGKILL if the process remains. PID identity is checked before the second signal to reduce PID-reuse risk. Permission denial can invoke the native macOS administrator dialog.
- Added a Firewall view backed by `socketfilterfw` for global enable/disable, stealth mode, block-all, signed-software options, and application allow/block/add/remove operations. Mutations use native macOS administrator authorization and are confirmed in the TUI.
- Startup now has a current-user view of Login Items and LaunchAgents. It can add either type, enable/disable current-user LaunchAgents, and remove a Login Item or LaunchAgent. LaunchAgent removal unloads the job and moves the plist into a dated `~/Library/Application Support/msp/StartupBackups/` directory; it does not remove the executable. Login Item Automation failures appear as an unavailable row with the error retained in CLI output.
- Added palette entries for firewall options and for navigating to the path/name forms used by firewall and startup controls. Screen actions execute through the CLI and stream their commands and results to Execution Logs; Chat / Ask code was not changed.
- Added network, startup, and firewall actions to their CLI argument parsers and interactive menus, with JSON output and updated `msp --help` examples.
