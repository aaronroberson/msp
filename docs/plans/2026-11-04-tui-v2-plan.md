# Plan: msp TUI v2 — Textual as the primary interface

**Date:** 2026-11-04
**Repo:** ~/macos-privacy-cli
**Decision (user):** "Build msp tui v2 in Textual as the primary interface."
Architecture principle follows the researched pattern (hermes / opencode): **the engine stays Python and is invoked through a stable surface (the `msp` CLI); the TUI is a thin client** that drives it.

## Goals

1. One polished, keyboard-first Textual app replaces the scattered inline menus as the default face of `msp` (and of bare `msp` with no command).
2. Command palette (opencode-style `ctrl+p`) that fuzzy-searches every TUI view and every runnable CLI verb.
3. Command runner pane: execute any `msp` verb + args as a subprocess, stream output into a scrollable log pane with exit code and duration. Non-interactive verbs run inline cannot be trusted (modules mutate `sys.argv`, call `sys.exit()` on exit codes, and rich-print apologetically through Textual's own screen) — subprocess is the safe rendering boundary.
4. Live table views (findings, network, startup, TCC, privacy status, snapshots) fed by real CLI JSON output in background workers (no blocking UI, no import-time singletons like v1).
5. Detail screen: Enter on any table row opens the full record; Esc/q dismisses it. Matches user controls: up/down navigate, space toggle, Enter confirm, q/Esc dismiss.

## Non-goals (original 2026-11-04 iteration)

- The original first iteration deferred write/kill/enable actions. The 2026-11-09 interaction extension below supersedes that limit for the scoped process, firewall, and current-user startup workflows.
- No Rust/Go rewrite; v1 (`src/tui.py`) stays importable as `msp tui --v1` escape hatch.

## Architecture

New module `src/tui_v2.py`:

- `Catalog` (`VIEWS`, `RUNNABLES`, `DANGEROUS_VERBS`) — single source of truth for the rail, palette, and runner suggestions.
- `CommandBroker` — builds argv from a shlex-parsed CLI line (`msp <verb> <args>`), spawns `sys.executable -m src.main ...` (PYTHONPATH pinned to the repo root), yields `(line, done, rc, duration)` tuples for the streaming log.
- `MspTUI(App)` — `Header` + left rail (`OptionList`, 28 cols) + content area that swaps panes.
  - `DashboardPane` — live status cards from CLI JSON output.
  - `TablePane` — generic table populated by a real CLI JSON command, with local row filtering.
  - Persistent command panel — shown on every screen; displays invoked commands, real output, exit status, and duration; `ctrl+c` stops the running job.
  - `DetailScreen(ModalScreen)`, `ConfirmScreen(ModalScreen)`, `HelpScreen(ModalScreen)`.
- `MspCommandProvider(textual.command.Provider)` + `Command` subclasses → palette hits for "open view" / "run verb" / "help".
- Default app bindings: `ctrl+p` palette, `q` quit, `?` help, `1–0` quick view jumps, `r` refresh, `ctrl+r` runner.

The 2026-11-08 UI refresh applies the local `.stitch/` palette and screen compositions: overview cards and live previews, findings inspector and severity filters, network tabs, inventory headers, privacy cards, snapshot capture confirmation, and a searchable command palette. The implementation deliberately excludes exported sample system records and labels. Navigation and refresh controls invoke CLI commands; their JSON output drives the visible data.

Binding UX (user requirement): cursor up/down (j/k works in tables via Textual), space toggles row lock in table panes, Enter opens detail / runs command, q & Esc dismiss/close everywhere.

## Interactive controls extension (2026-11-09)

The user approved extending the TUI from a read-and-runner interface into scoped, contextual controls. The live CLI remains the execution layer; TUI actions show their `msp` command and output in Execution Logs, while Chat / Ask remains free of control messages.

- Network tables expose Inspect and Stop for the selected process. Inspect collects live `ps` and `lsof` details. Stop sends SIGTERM, waits up to five seconds, then offers a separately confirmed SIGKILL only if the same process identity remains. Permission failures use macOS administrator authorization.
- The Firewall view reads `socketfilterfw`, exposes global state, stealth, block-all, signed-software settings, and application add/remove/block/allow controls. Mutations require TUI confirmation and use the native macOS authorization dialog.
- Startup controls are limited to the current user: enumerate Login Items and LaunchAgents, add Login Items or LaunchAgents for an app/executable, enable/disable LaunchAgents, and remove either startup item type. LaunchAgent removal unloads it and moves only its plist to a dated recoverable backup; the executable remains in place. Login Item enumeration reports Automation permission errors as unavailable data.
- The command palette includes the Firewall view/settings and focused form shortcuts for adding firewall rules, Login Items, and LaunchAgents. These shortcuts route users to real screen controls when they need to supply a path or name; no placeholder paths or sample records are used.
- New CLI operations retain JSON output and interactive menu entries. All mutating UI actions pass through confirmation and are recorded in Execution Logs.
